# Link Reliability Calculation

## 1. Overview

This folder contains the implementation for calculating link reliability scores for currently unobserved edges in the Sanak intertidal food web.

The reliability scores are calculated using the Stochastic Block Model (SBM) and partitions generated by the Metropolis algorithm.

The goal is to rank unobserved links according to how likely they are under the SBM and investigate the stability of these predictions across independent runs.

## 2. Methodology

Following Guimerà and Sales-Pardo (2009), the theoretical link reliability is

\[
R(v,w)=\frac{1}{Z}\sum_T
\frac{\ell_{T_vT_w}+1}{r_{T_vT_w}+2}
f(T,G^O),
\]

where:

- \(T\) is a partition of the network into SBM groups.
- \(\ell_{T_vT_w}\) is the number of observed links between the groups containing nodes \(v\) and \(w\).
- \(r_{T_vT_w}\) is the maximum possible number of links between these groups.
- \(f(T,G^O)\) is the SBM weight of partition \(T\).
- \(Z\) is the normalization constant.

Since summing over all possible partitions is computationally infeasible, Metropolis sampling is used to approximate this expression.

### Current implementation: Unweighted Monte Carlo average

For each partition retained by Metropolis, we calculate the conditional link probability:

\[
p_{vw}(T_i)=\frac{\ell_{T_i(v),T_i(w)}+1}{r_{T_i(v),T_i(w)}+2}.
\]

The final reliability score is the arithmetic mean across the \(M\) retained partitions:

\[
\hat R(v,w)=\frac{1}{M}\sum_{i=1}^{M}p_{vw}(T_i).
\]

**Why unweighted?**

In standard Metropolis sampling, partitions are visited according to their SBM probabilities. Therefore, the partition weights are already accounted for by the sampling process, and no additional weighting is required when calculating the Monte Carlo average.

The SBM weights are still essential inside the Metropolis algorithm, where they determine the acceptance probabilities of proposed partitions.

### Metropolis sampling and NMI

The updated Metropolis implementation separates the acceptance of proposed partitions from the selection of partitions to retain.

- Proposed moves are accepted or rejected based on the SBM weight.
- Normalized Mutual Information (NMI) is used to determine whether a partition is sufficiently different from the last retained partition to be saved.
- Previously encountered partitions may appear again in later samples.

This corrects the earlier implementation, in which the NMI condition also affected Metropolis acceptance.

**Important limitation:** Although this procedure is closer to the professor's workshop implementation, NMI-based retention can still influence the distribution of saved partitions. Therefore, the reliability estimates remain dependent on the sampling procedure and should be interpreted with this limitation in mind.

## 3. Implementation

### `Link_reliability.py`

Contains functions for:

- Identifying candidate missing links (currently unobserved node pairs).
- Calculating reliability scores across retained partitions.
- Converting reliability scores into a DataFrame.
- Computing descriptive statistics.
- Extracting the highest-scoring candidate links.

### `results_reliability.py`

Runs the complete pipeline using the partitions generated by Metropolis implementation, prints the results, and exports them to CSV.(just one run)

To run from the project root:

```powershell
py reliability_score/results_reliability.py
```

### `stability_analysis.py`

Performs repeated reliability calculations using the same model parameters but different random seeds.

The purpose is to investigate how sensitive the reliability scores and highest-ranked predictions are to randomness in the Metropolis algorithm.

The analysis compares:

- The number of retained partitions across runs.
- Summary statistics of the reliability scores.
- The mean and standard deviation of individual link reliabilities.
- The top 20 highest-scoring candidate links across runs.
- The frequency with which each link appears in the top 20.

To run from the project root:

```powershell
py reliability_score/stability_analysis.py
```

### Inputs

- Adjacency matrix of the observed network.
- Partitions retained by Metropolis.
- Number of SBM groups, \(K\).

The Metropolis log weights and initial log weight are included in the reliability function interface for compatibility but are not used in the unweighted reliability calculation.

### Outputs

The `results/` folder contains:

- `reliability_scores.csv`: Candidate links, taxon names, and reliability scores, ranked from highest to lowest. (just one run)
- `reliability_statistics.csv`: Descriptive statistics of the reliability scores. (just one run)

The optional `results/stability/` folder contains:

- `reliability_scores_run_1.csv` to `reliability_scores_run_5.csv`: Reliability scores from each independent run.
- `baseline_stability.csv`: Summary statistics and number of retained partitions for each run.
- `baseline_link_stability.csv`: Mean, standard deviation, minimum, and maximum reliability for each candidate link.
- `top20_comparison.csv`: The 20 highest-ranked predictions from each run, displayed side by side.
- `top20_frequency.csv`: Number of runs in which each candidate link appears among the top 20 predictions.

## 4. Current Results

The current implementation uses the updated Metropolis sampler with the following parameters:

| Parameter | Value |
|---|---|
| Number of SBM groups (\(K\)) | 16 |
| Initial convergence steps | 3,000 |
| Main Metropolis steps | 300,000 |
| NMI threshold | 0.95 |
| Number of nodes changed per proposal | 1 |

The network contains 235 nodes and 1,743 observed undirected edges, resulting in 25,752 candidate missing links.

The number of groups \(K=16\) is the current experimental setting and has not yet been selected through cross-validation.

### Reliability scores

In one run using the updated parameters, the Metropolis algorithm retained 204 partitions.

The resulting reliability scores had the following statistics:

- **Mean reliability:** 0.0503
- **Median reliability:** 0.0150
- **Maximum reliability:** 0.800

Compared with the original \(K=3\) baseline, the new scores show greater variation, with many low-reliability candidates and a smaller number of substantially higher-scoring links.

However, both the Metropolis procedure and the number of SBM groups changed, so these differences cannot be attributed to either change individually.

### Stability analysis

To investigate the sensitivity of the reliability estimates to randomness, the calculation was repeated five times with identical parameters and random seeds 42–46.

| Run | Retained partitions | Mean reliability | Maximum reliability |
|---|---:|---:|---:|
| 1 | 175 | 0.04975 | 0.82564 |
| 2 | 229 | 0.05063 | 0.79601 |
| 3 | 235 | 0.05062 | 0.81332 |
| 4 | 239 | 0.05050 | 0.81280 |
| 5 | 182 | 0.05022 | 0.82407 |

The mean reliability remains relatively consistent across runs, despite differences in the number of retained partitions.

The maximum reliability varies more noticeably, suggesting that individual high-scoring predictions can be sensitive to the sampled partitions.

### Stability of the top 20 predictions

The top 20 highest-scoring candidate links were compared across the five runs.

- 39 distinct candidate links appeared in at least one top-20 list.
- Two candidate links appeared in the top 20 in all five runs.
- The overlap between pairs of top-20 lists ranged from 7 to 17 links.

Two consistently highly ranked candidates were:

- Trochidae — Detritus complex.
- Katharina tunicata — Detritus complex.

Several other links appeared repeatedly, including links involving Bacillariophyta and Homo sapiens.

These results suggest that the overall reliability-score distribution is relatively stable, while the exact ranking of the highest-scoring links is more sensitive to Metropolis randomness.

**Stability does not imply predictive accuracy.** Cross-validation is still required to determine whether the SBM successfully predicts unobserved links.

## 5. Limitations and Next Steps

The current results are preliminary and subject to several limitations:

- The number of SBM groups \(K=16\) has not yet been validated.
- NMI-based partition retention may affect the Monte Carlo approximation.
- The reliability scores depend on the randomness of Metropolis sampling.
- The observed network is undirected, so predicted links do not identify predator-prey direction.
- High reliability indicates a strong prediction under the SBM, not confirmation of a biological interaction.

The next steps are:

1. Compare different values of \(K\) using cross-validation.
2. Evaluate predictive performance using metrics such as ROC AUC and precision@L.
3. Investigate differences in prediction performance across taxonomic groups and phyla.
4. Examine predicted links involving humans and assess their ecological interpretation.
5. Repeat the stability analysis using the final selected model configuration.

No reliability threshold has been selected. For now, candidate links are ranked by their reliability scores.
