# Link Reliability Calculation

## 1. Overview

This folder contains the implementation for calculating link reliability scores for currently unobserved edges in the Sanak intertidal food web.

The reliability scores are calculated using the Stochastic Block Model (SBM) and partitions generated by the Metropolis algorithm.

The goal is to rank missing links according to how likely they are under the SBM.

## 2. Methodology

Following Guimerà and Sales-Pardo (2009), the theoretical link reliability is

\[
R(v,w)=\frac{1}{Z}\sum_T
\frac{\ell_{T_vT_w}+1}{r_{T_vT_w}+2}
f(T,G^O),
\]

where:

- \(T\) is a partition of the network into SBM groups.
- \(\ell_{T_vT_w}\) is the number of observed links between the groups containing nodes \(v\) and \(w\).
- \(r_{T_vT_w}\) is the maximum possible number of links between these groups.
- \(f(T,G^O)\) is the SBM weight of partition \(T\).
- \(Z\) is the normalization constant.

Since summing over all possible partitions is computationally infeasible, Metropolis sampling is used to approximate this expression.

### Current implementation: Unweighted Monte Carlo average

For each partition retained by Metropolis, we calculate the conditional link probability:

\[
p_{vw}(T_i)=\frac{\ell_{T_i(v),T_i(w)}+1}{r_{T_i(v),T_i(w)}+2}.
\]

The final reliability score is the arithmetic mean across the \(M\) retained partitions:

\[
\hat R(v,w)=\frac{1}{M}\sum_{i=1}^{M}p_{vw}(T_i).
\]

**Why unweighted?**

In standard Metropolis sampling, partitions are visited according to their SBM probabilities. Therefore, the partition weights are already accounted for by the sampling process, and no additional weighting is required when calculating the Monte Carlo average.

The SBM weights are still essential inside the Metropolis algorithm, where they determine the acceptance probabilities of proposed partitions.

### Important limitation

The validity of this Monte Carlo approximation depends on obtaining representative samples from the target SBM distribution.

The current Metropolis implementation additionally uses an NMI threshold to restrict which partitions are accepted and retained. This differs from the procedure in Guimerà and Sales-Pardo (2009), where mutual information is used to reduce correlation between recorded samples.

Consequently, the current reliability scores should be treated as preliminary until the sampling procedure has been reviewed.

## 3. Implementation

**`Link_reliability.py`**

Contains functions for:

- Identifying candidate missing links (currently unobserved node pairs).
- Calculating reliability scores across retained partitions.
- Converting reliability scores into a DataFrame.
- Computing descriptive statistics.
- Extracting the highest-scoring candidate links.

**`results_reliability.py`**

Runs the pipeline using the partitions generated by Sorin's Metropolis implementation, prints the results, and exports them to CSV.

To run from the project root:

```powershell
py reliability_score/results_reliability.py
```

### Inputs

- Adjacency matrix of the observed network.
- Partitions retained by Metropolis.
- Number of SBM groups, \(K\).

The Metropolis log weights and initial log weight are currently included in the function interface for compatibility but are not used in the unweighted reliability calculation.

### Outputs

The `results/` folder contains:

- `reliability_scores.csv`: Candidate links, taxon names, and their reliability scores, ranked from highest to lowest.
- `reliability_statistics.csv`: Descriptive statistics of the reliability scores.

## 4. Current Baseline

The reliability scores are calculated using the partitions generated by the Metropolis algorithm. Therefore, the parameters used in Metropolis directly affect the resulting reliability scores.



The current baseline uses the following parameters:

| Parameter | Value |
|---|---|
| Number of SBM groups (K) | 3 |
| Initial convergence steps | 100 |
| Main Metropolis steps | 100,000 |
| NMI threshold | 0.7 |
| Number of nodes changed per proposal | 20 |
| Retained partitions | 41 |

For the current run, the network contains 235 nodes and 1,743 observed edges, resulting in 25,752 candidate missing links.

The reliability scores have the following summary statistics:

- **Mean reliability:** 0.0610
- **Maximum reliability:** 0.2005
- **Median reliability:** 0.0515

These results are preliminary. Repeated runs with the same parameters have produced similar mean reliability scores (approximately 0.061), but different numbers of retained partitions and different highest-scoring candidate links. This suggests that the overall mean is relatively stable, while the stability of individual link predictions still needs to be investigated.

**No reliability threshold has been selected yet.** Before deciding whether a threshold is appropriate for identifying likely missing links, we should finalize the Metropolis settings and evaluate the model using cross-validation.
